# ADR-0007 PH7 계약: 마켓플레이스 색인·가져오기, GitHub·GHES 내보내기

- 상태: 승인 (리드, 2026-10-29) — PH7 착수 전, 상세는 design.md 9장
- 관련: PRD MKT-01·MKT-02·EXP-02, project-rules 보안 규칙(마켓 위험 패턴, 토큰 미저장), ADR-0006

## 맥락
PoC는 마켓 목록이 하드코딩돼 있고, 가져온 스킬은 자리표시 SKILL.md만 만든다. GitHub 푸시는 계획만 보여 준다. 실제 기능을 만들려면 세 가지가 필요하다.
1. 네트워크 접근(소스 저장소)
2. 신뢰할 수 없는 콘텐츠의 안전한 포함
3. 토큰 처리

## 결정
1. **스키마 확장(G2 동결 예외)**: 가져온 스킬에 실제 파일(`files`)과 출처 커밋(`ref`)을 담는다. GitHub 대상에 `mode`·`baseUrl`·`branch`를 둔다. 모두 선택 필드라 기존 입력은 그대로 통과한다.
2. **위험 판정은 core의 순수 함수**:
   - 서버 색인과 core 불변식이 같은 `scanSkillRisk`를 쓴다.
   - 불변식은 입력의 `flags`를 믿지 않고 `files`로 다시 계산한다. 화면이나 입력 조작으로 확인 단계를 건너뛸 수 없다.
3. **색인은 선택 배포 서버(Fastify)가 맡는다**:
   - 브라우저는 임의 저장소에 직접 접근하지 않는다(CORS·폐쇄망·토큰 노출 방지).
   - 서버가 없으면 마켓은 비활성 안내만 보인다(설치형 기본 동작 유지).
   - 사내 Git은 시스템 `git`을 인자 배열로 호출한다. 비공개 저장소 토큰은 서버 환경 변수 이름으로만 참조한다.
4. **가져온 파일은 원문 그대로, 실행 권한 없이(644)** 넣는다.
   - `sources.lock`에 출처 커밋과 파일별 sha256을 남겨, 사용자가 출처와 대조할 수 있게 한다.
   - 실행 권한이 필요하면 사용자가 직접 `chmod` 한다. 위험 코드 `SCRIPTS`가 이를 알린다.
5. **GitHub 내보내기는 브라우저에서 바로 호출**(`@octokit/core`, 지연 로딩)한다.
   - create 모드는 부모 없는 커밋과 ref 강제 갱신으로 이력을 커밋 1건으로 만든다.
   - pr 모드는 기존 파일을 유지하는 base_tree 위에 1커밋 + PR을 만든다.
   - 토큰은 한 번 쓰고 버린다.
   - GHES CORS 중계(서버)는 P2로 미룬다.
   - project-rules의 "Octokit"은 `@octokit/core`(경량)로 충족한다.
6. **기본값 불변**: `imported: []`이고 `export` 미지정이면 생성물은 v0.2.0과 같다. golden은 유지한다.

## 결과
- 개발자별 계약 시험:
  - dev-1(core): 위험 판정 표, 불변식, 렌더, lock, sha256, tree 계획
  - dev-2(exporter·server): 서버 API를 가짜 fetch와 로컬 `file://` git 저장소로 시험, push를 가짜 GitHub API로 시험, E2E
  - dev-3(web): 마켓 화면과 내보내기 화면
- 실제 GitHub 실기(사용자 계정, 임시 저장소 생성·삭제)는 게이트 전에 사람의 확인을 받아 한 번 수행한다.
