# AgentForge PRD (개발용 요약판)

> 이 문서는 AgentForge 자체를 개발하기 위한 요구사항이다. 기능 ID는 tasks.md·커밋·리뷰에서 그대로 쓴다.
> 우선순위: P0 = MVP(G4) 필수 / P1 = 정식 출시(G6) 필수 / P2 = 출시 이후

## 1. 개요
| 항목 | 내용 |
| --- | --- |
| 제품 | Claude Code 멀티 에이전트 개발 환경 생성기 |
| 원칙 | AI 미호출 · 개발 내용 비관여 · 사용자 PC 명령 미실행 · 인증 정보 미취급 |
| 대상 | 개인 개발자, SI/SM 개발팀 리드, 폐쇄망 기업 |
| 동작 기준 | docs/reference/poc.html (생성 로직과 화면 흐름) |

## 2. 목표
- 처음 쓰는 사용자가 10분 안에 환경을 생성하고 VS Code에서 병렬 개발을 시작한다.
- 생성된 셸 스크립트는 지원 환경(macOS, Linux, WSL, Dev Container)에서 수정 없이 동작한다.

## 3. 사용자 흐름
1. 환경 기본 설정 → 2. 문서 미리보기 → 3. 에이전트·루틴 → 4. 스킬 → 5. 터미널·VS Code → 6. 내보내기(ZIP / GitHub)

## 5. 비기능 요구사항
| 항목 | 내용 |
| --- | --- |
| 폐쇄망 | 설치형은 외부 접속 없이 동작(마켓 색인은 사내 Git 또는 수동 업로드) |
| 보안 | 비밀 값 미수집·미저장, 셸 인자 이스케이프, 가져온 스킬 위험 검사 |
| 성능 | 설정 변경 후 미리보기 갱신 100ms 이내, ZIP 생성 2초 이내 |
| 호환 | 생성물: bash 4+, tmux 3.2+, git 2.30+, Claude Code 현재 버전 |

### 8.2 단계별 상세

**PH0 준비**
- 산출물: PoC로 생성한 개발 환경, CLAUDE.md의 `@docs/project-rules.md` 연결, 비공개 저장소
- 완료 조건: `/agents`에 6종 표시, 제품 원칙 4가지 응답 확인

**PH1 설계**
- 입력: 이 문서, `docs/project-rules.md`, `docs/reference/poc.html`
- 산출물: `docs/design.md`(스키마·불변식·core API·렌더러 대응표), `docs/tasks.md`(PH3·PH4 작업, 담당·선행·완료 기준), `docs/adr/0001~0003`
- G1: 스키마가 PoC 설정 항목을 모두 담음 / core에 I/O 없음 / 담당 폴더 비중복 / P0 기능 ID 전부 배정

**PH2 골격·공통**
- 산출물: pnpm 모노레포, zod 스키마와 불변식 테스트, core API 시그니처, `test:scripts`, CI
- G2: build·typecheck·test·CI 통과. 이후 스키마 변경은 리드 승인 절차로만

**PH3 세로 한 줄**
- 산출물: PoC 기준 출력(`tests/golden`), core 렌더러(PoC gen* 함수 이식), `toZip`, 최소 화면(1단계 + 미리보기 + ZIP)
- G3: golden 일치, bash -n·shellcheck·bats 통과, 받은 ZIP으로 `setup.sh` → `run-agents.sh 1` 에서 tmux 창 생성

**PH4 MVP 병렬 개발**
- 담당: dev1 core·templates(내장 스킬 본문, 렌더러 보강) / dev2 exporter·bats·E2E / dev3 web 6단계 화면
- 완료 조건: 각 작업이 개발별 검증 통과 후 main 병합, 매일 통합 테스트 통과

**PH5 통합·실기 검증**
- 실기 점검: 환경 4종(macOS, Ubuntu, WSL, Dev Container) × 구성 3종(Claude 단일 / 제공자 혼용 / 개발 1명·검증 끔)

- G4: 점검표 12칸 통과, 보안 조치 완료

### 8.3 단계 운영 규칙
- 한 단계 안에서는 그 단계의 기능 ID만 tasks.md에 올린다. 다음 단계 작업은 단계 전환 후 architect가 분할한다.
- 단계를 넘어갈 때마다: 게이트 확인 → "현재 단계" 갱신 → 태그 → `docs/report.md`에 단계 결과 요약.
- 앞 단계로 돌아가야 하는 결함(스키마·생성 규칙 오류)은 ADR로 기록하고 리드가 처리한 뒤 다시 진행한다.
